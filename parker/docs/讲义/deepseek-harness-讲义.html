1.2 · THREE IDEAS

1.2 DeepSeek Harness 的三大核心特性

Composition

Everything is a plugin

模型、工具、会话、沙箱、存储、循环、调度与 UI，全部由插件贡献。

Evidence

Every run is traceable

模型看到的输入与工作过程写入会话事件流，可以恢复、分叉与回放。

Preset

Multiple runtime modes

四种模式不是四个模型，而是四套不同的 Harness 能力组合。

STANDARD标准模式完整 Coding Agent：文件、Shell、搜索、Skills、计划、子 Agent。
CODE / PTCPTC 模式通过一段 TypeScript 程序组合多步工具调用。
MINIMAL极简模式只保留持久 Bash 与 str_replace_editor。
CORDIS创造模式在 Standard 上增加运行时检查、插件实验与 Preset 创作。
先记住三句话：能力可组装、过程可追踪、运行模式可替换。

2.2.1 什么是 PTC

模型主要看到一个 run_code，再由它编排 Harness 内部工具。

PTC CALL PATH讲义示意图 · 非官方

2.2.2、run_code 工具 Schema

TYPE DEFINITIONS
type RunCodeArgs = {
  code: string        // 异步 TypeScript 函数体
  description: string // 显示在 UI 中的用途说明
}

type RunCodeOutput = {
  logs: string[]      // console.log 输出
  result?: JsonValue // return 的 JSON 值
}

2.2.3、run_code 能编排的工具

Code Mode 中，每个当前 Agent 可见、已经注册的 Harness 工具，都会自动成为 await tools.<name>(args)。官方源码 · Tool authoring reference ↗

可编排范围来自 Harness 工具注册表，不是操作系统里的任意命令，也不是一份写死的工具名单。

Registry

先注册

Cordis Plugin 通过 ctx.tools.register(...) 把工具交给 Harness。

Visible

再筛选

Preset、作用域和权限决定这个 Agent 最终能看见哪些工具。

SDK

自动生成

Code Mode 根据可见工具的 Schema 生成本轮 tools SDK。

常见示例：read、write、edit、bash、web_search。实际名单以当前会话生成的 SDK 为准。

想增加一个能被 run_code 编排的工具

开发一个 Tool Plugin，并把工具注册到 Harness。插件加载且工具对当前 Agent 可见后，Code Mode 会自动把它加入 run_code 的生成 SDK，无需修改 run_code。
后续实验3.1.3 动手开发 1 个 Tool 插件跳转学习 →

2.2.4、PTC 与直接写脚本让模型调用的区别

对比项PTC直接写脚本
定位开放式任务的临时工具编排固定能力的可复用封装
执行run_code 调用 tools.xxx()Bash、Node、Python
权限子调用进入 Harness 工具流程主要依赖进程与文件沙箱
中间结果程序内处理，只返回摘要脚本自行控制输出

2.3 · CREATOR

2.3 创造模式

2.3.1、什么是创造模式

用于创建自定义 Agent preset：具备标准模式的全部能力，并提供运行时检查、插件实验和 preset 创作指导。官方源码 · cordis/preset.yml ↗

创造什么？

Plugin

创造插件

检查运行时，开发和调试 Cordis Plugin，为 Harness 增加工具、服务或 UI。

Preset

创建 Agent Preset（Agent 预设模式）

组合 Persona、工具、Skills 与工作流，形成可以再次选择的 Agent 模式。

官方描述的重点：创造模式保留 Standard 的完整开发能力，再增加运行时检查、插件实验和 Preset 创作指导。

2.3.2、多出来的 2 个 Skill

2.3.3、能输出的产物

Runtime

动态 Cordis 插件

临时增加工具、服务、事件、浏览器面板、按钮、主题与样式。

Disk

自定义 Agent preset

持久保存 Persona、工具、Skills、子 Agent、工作流与上下文能力。

2.3.4、适用场景和时效性

产物时效性适合场景
动态 Cordis 插件宿主进程重启后消失临时实验、调试、当前 UI 增强
自定义 Agent preset保存到磁盘，重启后存在长期使用的 Agent 能力组合

3.1.3 动手开发 1 个 Tool 插件

工具插件把“可调用能力”注册进模型工具集合。

greet-tool.ts · core
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: { name: { type: 'string', required: true } },
    async execute(args) { return `Hello, ${args.name}!` }
  }))
}

3.3.1 Preset 是什么

A preset is a directory holding one agent.cordis.yml.官方源码 · dsh-agent-presets README

通俗地说：Preset 是一套给 Session 使用的 Agent 能力组合。

3.3.5 官方四种内置模式有什么区别

项目StandardCode / PTCMinimalCreator
工具呈现Native，多工具主要呈现 run_codeNative，两个工具Native，多工具
Skills项目与用户 Skills同 Standard无 Skill 工具Standard + 2 个 Cordis Skill
Plan / Subagent有 / 有有 / 有无 / 无有 / 有
主要用途日常开发程序化工具调用最小环境创建 Plugin 与 Preset

Standard：标准模式

完整工具组合，动态组装项目指令、Skills、会话状态与 Host 提示词。

Code / PTC：程序化工具调用模式

Minimal：极简模式

固定提示词，只保留持久 Bash 与 str_replace_editor。

Cordis / Creator：创造模式

保留 Standard 能力，再增加运行时检查、插件开发和组合编辑指导。
